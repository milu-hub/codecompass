## 本轮验收发现并修复的问题（如实记录）

跑「真 MySQL + 持久化数据」的定局全量时，暴露出 **2 类测试断言问题**（产品功能本身正常）：

1. **JSON 列格式规范化**：`learning_paths.path_json` / `quizzes.quiz_json` 的回环断言原先比较**字节相等**，
   而 MySQL 的 JSON 类型会规范化格式（去空格、按内部规则排键），H2 则原样存文本 —— 断言只在 H2 成立。
   **修正为「解析后 JSON 树相等」**（语义口径，两库都成立且更正确）。
2. **持久化库的测试残留**：仓储测试用固定键（`sha-unique`、`quiz-h2-1`）插入，真 MySQL 不随测试重建，
   上一轮的残留行会让本轮的唯一约束插入直接失败。**修正为 @Transactional 自动回滚 + 每轮唯一键**。

这两类问题在「只用 H2」的默认单测里永远不会暴露 —— 这正是 T23 要求「单元用 H2、集成用 MySQL」的价值：
它同时验证了 **同一套代码/迁移在两种方言下都成立**。
